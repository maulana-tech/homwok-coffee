Jawaban untuk Setiap Pertanyaan Penguji

Sistem POS dengan perhitungan HPP metode FIFO — Homwok Coffee Hidayat 2023 · Weygandt 2019 · Pressman 2020 · Fielding 2000

I.Pendahuluan

Latar Belakang

Jika penguji bertanya "Mengapa Anda mengangkat topik ini?"

UMKM industri kopi masih pakai pencatatan manual — rentan human error, tidak ada laporan real-time, tidak ada antrean FIFO. Homwok Coffee kesulitan hitung HPP akurat karena fluktuasi harga bahan baku (biji kopi, susu, sirup) antar periode. Dampak: harga jual tidak tepat, laba bias, stok lemah, risiko kedaluwarsa → kerugian finansial.

Solusi — Sistem POS berbasis web dengan pengelolaan persediaan FIFO otomatis. FIFO krusial untuk F&B karena selaras dengan alur fisik bahan baku perishable.

Rumusan Masalah

Jika penguji bertanya "Jadi, apa yang Anda teliti/buat?"

Bagaimana merancang dan membangun Aplikasi Penjualan Kasir (POS) berbasis web terintegrasi dengan fitur perhitungan HPP menggunakan metode FIFO pada Homwok Coffee.

Ruang Lingkup

Gunakan sebagai "tameng" jika penguji minta fitur tambahan.

Hanya modul penjualan (kasir) dan modul persediaan. Metode hanya FIFO — tidak bahas LIFO/Average. Fokus pada bahan baku perishable.

II.Dasar Teori & Tinjauan Pustaka

Point of Sale (POS)

Sistem elektronik untuk proses transaksi penjualan. Berkembang dari mesin kasir menjadi sistem informasi terintegrasi — pencatatan, manajemen persediaan, pelaporan (Hidayat & Farell, 2023). POS berbasis web percepat transaksi & tingkatkan pelayanan (Darmawan, 2021).

Persediaan (Inventory)

Aktiva untuk dijual atau untuk produksi (Weygandt et al., 2019). Tiga jenis: bahan baku, barang dalam proses, barang jadi. Pada F&B perishable, pengendalian persediaan berkaitan langsung dengan risiko kedaluwarsa.

Metode Penilaian Persediaan

FIFO Dipilih

Pertama masuk = pertama keluar. HPP dari pembelian terlama; persediaan akhir = harga terbaru.

LIFO Tidak

Kebalikan FIFO. Tidak diakui PSAK Indonesia, jarang diterapkan.

Average Tidak

Biaya berdasarkan harga rata-rata seluruh unit, tanpa urutan masuk.

Kenapa FIFO? (1) Selaras alur fisik F&B → hindari kedaluwarsa. (2) Nilai persediaan akhir mendekati harga pasar terkini → lebih representatif.

Harga Pokok Penjualan (HPP / COGS)

Akumulasi seluruh biaya langsung untuk barang yang terjual dalam satu periode (Weygandt et al., 2019). Komponen pada Homwok: biji kopi, susu, sirup, paper cup, plastic cup, sedotan yang terpakai untuk menu terjual.

HPP = Persediaan Awal + Pembelian Bersih − Persediaan Akhir

Algoritma FIFO

Diimplementasikan dengan antrian lot pembelian (tanggal, kuantitas, harga/unit). Saat transaksi: potong dari lot paling awal; jika kurang, lanjut lot berikutnya. HPP = akumulasi biaya lot terpotong.

Catatan — HPP = harga lama, persediaan akhir = harga baru. Saat inflasi, FIFO → HPP lebih rendah, laba kotor lebih tinggi vs Average.

Bill of Materials (BOM / Resep)

Daftar terstruktur bahan + takaran untuk satu unit produk jadi (Heizer et al., 2020). Penghubung modul penjualan-persediaan: satu menu terjual → diterjemahkan ke bahan baku sesuai resep → dipotong dari antrian lot FIFO.

Arsitektur & Teknologi

Client-Server & RESTful API

Arsitektur decoupled. Komunikasi via REST — stateless, HTTP, GET/POST/PUT/DELETE (Fielding, 2000). Format: JSON. Logika bisnis (FIFO, HPP) penuh di backend.

Laravel & MVC (Backend)

Framework PHP dengan pola Model-View-Controller (Pressman & Maxim, 2020). Pada decoupled, View digantikan respons JSON via REST API.

React.js & Next.js (Frontend)

React — library JS komponen reusable + Virtual DOM (Naresvari & Susetyo, 2025). Next.js — routing, SSR, optimasi. Berjalan di Node.js (Pratama & Raharja, 2023).

Basis Data MySQL

RDBMS dengan tabel terelasi (Connolly & Begg, 2015). Diakses Laravel via ORM Eloquent. Simpan: master menu, resep, pembelian+lot FIFO, penjualan, log pemakaian bahan.

Tinjauan Pustaka (Kebaruan)

Jika penguji bertanya "Apa bedanya dengan penelitian kakak tingkat sebelumnya?"
  • vs Darmawan (2021), Khumairoh (2025): hanya POS kasir, tanpa integrasi HPP FIFO
  • vs Candrasari (2022): fokus klinik medis
  • vs Cahyanto (2024), Alfionita (2024): fokus ritel, tanpa dekomposisi resep minuman
Novelty — Satu-satunya yang mengintegrasikan POS kasir dengan pemotongan HPP real-time via dekomposisi lot FIFO khusus F&B (BOM).

III.Analisis & Perancangan

Deskripsi Sistem

Arsitektur Terpisah

Backend (Laravel) = REST API. Frontend (Next.js/React) = antarmuka.

Hak Akses (Role-Based)

Barista: input master, pembelian, POS kasir, cetak struk. Manager: dashboard analitik & laporan.

Non-Fungsional & Keamanan

Senjata rahasia Anda jika dosen ragukan keamanan sistem saat toko ramai.
  • Integritas Data — pembaruan stok dalam satu database transaction dengan row locking untuk mencegah race condition (kasir tekan tombol bayar bersamaan)
  • Kecepatan — algoritma FIFO wajib dieksekusi di bawah 3 detik
  • Keamanan — kata sandi dienkripsi dengan hashing

Contoh Numerik · Pemotongan Lot FIFO

Tiga lot pembelian biji kopi, penjualan mengonsumsi 6.000 g:

Pemotongan FIFO

Sumber Qty Harga Subtotal
Lot 15.000 gRp120Rp600.000
Lot 21.000 gRp135Rp135.000
Total6.000 gRp735.000

Sisa: Lot 2 = 4.000 g, Lot 3 = 5.000 g → persediaan akhir = (4.000 × Rp135) + (5.000 × Rp150) = Rp1.290.000 (harga terbaru).

Data Alur Diagram (DAD)

Level 0: Barista input → Sistem proses → Manager terima laporan. Level 1 (6 proses): (1) pegawai, (2) bahan baku, (3) resep, (4) pembelian, (5) penjualan (inti FIFO), (6) laporan.

Input & Output

Input Krusial

Form Transaksi Kasir — algoritma FIFO dipicu di latar belakang setelah pembayaran.

Output Manajerial

  • Penelusuran HPP — bukti bahan, lot, harga (validasi FIFO per nota)
  • Kartu Persediaan — mutasi masuk/keluar/saldo per bahan
  • Laba Rugi Kotor — omzet − total HPP riil

RingkasanJawaban Singkat

"Kenapa FIFO?"

Selaras alur fisik F&B + persediaan akhir ≈ harga pasar.

"Kenapa web?"

Multi-user, tanpa instalasi, fleksibel di semua perangkat.

"Bagaimana keamanannya?"

DB transaction + row locking + password hashing.

"Apa kebaruannya?"

POS + HPP FIFO real-time + BOM khusus F&B.
